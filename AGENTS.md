# AGENTS.md: Ledgerline engineering conventions

This file is the single source of truth for anyone changing this repository, human or AI agent.
`CLAUDE.md` points here. If a rule below conflicts with a habit, the rule wins.

## 1. Purpose and the honesty rule

Ledgerline is an **internal engineering demonstration by SpecShield Labs**: a reliable order and payment
event processing service (outbox, webhooks, idempotency, a mock payment provider and chaos experiments).

- **Synthetic data only.** No real cardholder data, PANs, bank details or personal data, ever, including in
  tests, fixtures, logs, screenshots and issues.
- **Not a production payment system.** It is not PCI DSS scoped and must never be presented as if it were.
- **No fabricated metrics.** Every number in the README, docs, PRs or slides (throughput, latency, coverage,
  mutation score, uptime) must come from a run that anyone can reproduce from this repo. State how it was
  measured. If you have not measured it, do not write it. Badges show live CI values or stay placeholders.
- If you cannot verify something (a version, a behaviour, a benchmark), say so explicitly.

## 2. Layout

```
ledgerline-api/   Spring Boot 4 service (Java 25), Maven module
ops-console/      React operations console (React 19, TypeScript, Vite), served from the jar
```

Package root `com.specshield.ledgerline`:

| Package       | Responsibility                                                        |
|---------------|-----------------------------------------------------------------------|
| `domain`      | Pure model: entities, value objects, domain events, invariants        |
| `application` | Use cases; orchestrates domain and ports; owns transactions           |
| `web`         | Controllers, DTOs, problem+json mapping                               |
| `persistence` | JPA entities, Spring Data repositories, mapping to and from domain    |
| `webhook`     | Inbound/outbound webhooks, signatures, delivery                       |
| `outbox`      | Transactional outbox and relay                                        |
| `mockpay`     | Synthetic payment provider (never a real network)                     |
| `chaos`       | Public chaos scenarios on fresh synthetic orders (needs MockPay)      |
| `demo`        | Demo data lifecycle: seeding and the nightly reset (ShedLock)         |
| `config`      | Spring wiring: security, `Clock`, OpenAPI                             |

## 3. Architecture rules (enforced by `ArchitectureTest` where possible)

1. **`domain` has no Spring, JPA or web imports.** No `org.springframework..`, `jakarta.persistence..`,
   `..web..` or `..persistence..` dependencies. (LL-A01)
2. **Controllers never call repositories.** `web` must not depend on `persistence`; go through
   `application`. (LL-A02)
3. **Money is `long` minor units (cents) with ISO 4217 currency `"USD"`.** Never `double`/`float`, never
   `BigDecimal` for stored amounts. Amount and currency always travel together.
4. **All times are UTC `java.time.Instant`.** No `LocalDateTime`, `Date` or zone-less timestamps in the
   domain, API or database (`timestamptz`). Hibernate is configured with `jdbc.time_zone=UTC`.
5. **Inject `java.time.Clock` everywhere time matters.** Never call `Instant.now()` / `System.currentTimeMillis()`
   without a `Clock`. The production bean is `Clock.systemUTC()` (`config.ClockConfig`); tests use
   `Clock.fixed(...)` or a mutable test clock.
6. Schema changes are forward-only Flyway migrations in `src/main/resources/db/migration`
   (`V<n>__description.sql`). Hibernate only validates (`ddl-auto: validate`).

## 4. Error format

**Every error response is RFC 9457 `application/problem+json`**, including validation errors, 404s,
405s, security failures (401/403) and unexpected 500s. Use Spring's `ProblemDetail`; set a stable `type`
URI and `title` per error kind. Never leak stack traces, exception class names or SQL
(`server.error.include-stacktrace: never`).

Problem `type`s are URNs from `web.ProblemTypes` (`urn:ledgerline:problem:<slug>`). Add a constant there for a
new error kind; never reuse one for a different meaning, because clients branch on it.

### API contract

- `docs/openapi.json` is generated by `OpenApiDocIT` (LL-C01) during `./mvnw verify` and **must be committed**.
  CI fails if it is stale, and fails a PR whose API change is backward incompatible with the base branch
  (`openapi-diff --fail-on-incompatible`). A breaking change needs a new API version, not an edit. The only
  exception is a break a maintainer approves explicitly by labelling the PR `api-break-approved` (CI then warns
  instead of failing); say why in the PR.
- State-changing endpoints require `Idempotency-Key`; it is handled by `web.IdempotencyFilter` and
  `application.IdempotencyService`, not in controllers.
- Every state-changing command writes an `audit_log` row in the same transaction as the change.

### Webhooks and provider events

- Provider events enter only through a signed webhook (`webhook.WebhookSignatureVerifier`): raw bytes, constant
  time `MessageDigest.isEqual`, 300 s tolerance. Never log or echo secrets or signature values.
- Every event goes through the inbox and `OrderEventSequencer` under a `SELECT ... FOR UPDATE` order lock, in one
  transaction with the audit and outbox rows. Never apply a provider event to an order directly.
- Design rationale: [ADR 0002](docs/adr/0002-webhook-signature-and-inbox.md). Record significant decisions as
  ADRs in `docs/adr/`.

### Security, limits and the public demo

- Access rules live in `config.SecurityConfig` only: public paths are listed explicitly, admin paths need HTTP Basic
  (`VIEWER` reads, `ADMIN` changes), everything else is denied. A new endpoint is denied until you add it there.
- Accounts are BCrypt hashes from configuration (`ledgerline.security.users`); never commit a real password or hash.
  The audit actor for admin actions is the authenticated user name, never a client-supplied header.
- Public endpoints are rate limited per client IP (`web.RateLimitFilter`). `X-Forwarded-For` is trusted only from the
  configured proxy CIDRs. Do not add another way to pick the client IP.
- Chaos scenarios only create and change their own new orders, through MockPay's real signed webhooks
  (`mockpay.MockPayScripts`). Never let a scenario take an order id from the caller.
- The demo reset (`demo.DemoReset`) runs only under the ShedLock lock `demo-data`; call it, never
  `DemoDataService.reset` directly from new code. Tests must not truncate `shedlock` (ShedLock caches lock rows).

### Outbox and merchant notifications

- A merchant notification is an `outbox` row written through `application.MerchantNotifications` **inside the
  transaction that changes the order**. Never call a merchant (or any external system) from a request
  transaction, and never write the row in a separate transaction.
- Delivery is **at-least-once and unordered**. Receivers deduplicate by `Ledgerline-Event-Id` (the outbox id).
  Do not promise exactly-once or ordered delivery in docs or code comments.
- The relay (`outbox` package) talks to the database only through `application.OutboxStore` (ArchUnit rule).
  Result updates are conditional on the claim (`status = 'IN_FLIGHT' AND claimed_at = ?`); keep them that way.
- Backoff is `outbox.BackoffPolicy`: pure, with an injected `RandomGenerator`. Tests use a seeded generator.
- Design rationale: [ADR 0003](docs/adr/0003-transactional-outbox.md).

## 5. Testing rules

- **Every behaviour change ships with tests.** No exceptions for "small" changes.
- **Integration tests use Testcontainers PostgreSQL 17 (`postgres:17-alpine`), never H2.** Use
  `@ServiceConnection`. Integration test classes end in `IT` (run by failsafe). Unit tests end in `Test`
  (run by surefire).
- **Test names follow `LL-XXX description`** (via `@DisplayName`) using IDs from the test catalogue when one
  exists for that behaviour. Do not invent catalogue IDs; if none exists, use a plain description.
- Tools available: JUnit 6 (Jupiter), AssertJ, ArchUnit, jqwik (property-based), WireMock (HTTP fakes),
  REST Assured, Testcontainers.
- Tests that depend on time use an injected `Clock`, never sleeps or wall-clock assertions.
- Coverage is gated by JaCoCo (line coverage, see `jacoco.line.minimum` in `ledgerline-api/pom.xml`).
  Raise the gate as code lands; never lower it to get a build through.
- Mutation testing (PIT) is gated at 70 % on `domain`, `webhook`, `outbox` and `application` (LL-N02), with unit
  tests only. New logic in those packages needs unit tests that would catch a changed condition or return value, not
  only integration tests.

### ops-console

- TypeScript `strict`; API types are generated from `docs/openapi.json` (`npm run generate:api`) and committed.
  Never hand-write API types; CI fails when they are stale.
- Unit tests: Vitest + Testing Library + MSW (`*.test.ts(x)`), using catalogue IDs `LL-F..`. Query by role and
  accessible name, not by class or test id, unless the value is deliberately volatile.
- E2E: Playwright (`e2e/`, IDs `LL-E..`) against `docker compose -f docker-compose.yml -f docker-compose.e2e.yml`.
  Screenshot baselines are per platform; regenerate the Linux ones with `scripts/e2e-docker.sh --update-snapshots`
  (the pinned Playwright image CI uses), never on a developer's host.
- Accessibility is a requirement: every status shows text and an icon, not colour alone; everything works with a
  keyboard and has a visible focus ring; axe (LL-E06) must report no serious or critical violations in either theme.
- Polling budget: one visitor stays well under the 240/min public rate limit (timeline 1 s only while a scenario
  runs). Do not add polling without checking it.
- Use Node 22.23.4 and npm 11.21.2 (the Maven build downloads them into `ops-console/node`; `PATH=$PWD/node:$PATH`).
  npm 10 cannot resolve this dependency tree.

### Evidence and observability

- `evidence/latest.json` is assembled by CI from reports (`evidence/assemble.mjs`). Never add a number to it, to the
  README or to a PR that a report did not produce; a missing measurement is `null` and stays visible as such.
- Spans: name custom observations `<area>.<action>` (`webhook.verify`, `outbox.deliver`); low-cardinality tags only
  for values with a small fixed set (outcome, event type), ids as high-cardinality tags.
- Logs: put `orderId` in the MDC where an order is known (it reaches the prod JSON logs); never log secrets,
  signatures or request bodies.

## 6. Commands

Requires JDK 25 (`JAVA_HOME` must point at it) and Docker (for Testcontainers and Compose).

| Command | What it does |
|---|---|
| `./mvnw verify` | Compile, format check (Spotless), unit + integration tests, coverage report + gate, SBOM |
| `./mvnw spotless:apply` | Format the code (palantir-java-format) |
| `docker compose up --build` | Start PostgreSQL 17 and the app (API + console) on http://localhost:8080 |
| `./mvnw verify -Dskip.frontend` | Backend only, without building ops-console |
| `cd ops-console && npm run dev` | Console dev server on http://localhost:5173, proxying the API on :8080 |
| `cd ops-console && npm run lint && npm run typecheck && npm test && npm run build` | Console checks (as CI) |
| `cd ops-console && npx playwright test` | E2E against a running stack (`E2E_BASE_URL`, default http://localhost:8080) |
| `ops-console/scripts/e2e-docker.sh` | The same E2E suite in the pinned Linux Playwright image, as CI runs it |
| `./mvnw -Pmutation -Dskip.frontend test-compile pitest:mutationCoverage` | PIT, fails below 70 % (LL-N02) |
| `perf/run.sh` | k6 load test + database check (LL-N01); stack up with `docker-compose.perf.yml` first |
| `node --test evidence/assemble.test.mjs` | Evidence assembler tests (LL-N08) |
| `scripts/fresh-clone-check.sh` | Quick start from a clean state: compose up, healthy within 180 s, one scenario, tear down (LL-N06) |
| `docker run --rm -v "$PWD:/input:ro" -w /input lycheeverse/lychee:0.24.2 --config lychee.toml './**/*.md'` | Link and anchor check of all Markdown, as CI's `link-check` |

Docker notes: with Colima, export `DOCKER_HOST=unix://$HOME/.colima/default/docker.sock` and
`TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock` before `./mvnw verify`. Compose host ports
are overridable with `LEDGERLINE_HTTP_PORT` / `LEDGERLINE_DB_PORT`.

Note: `./mvnw -Pmutation pitest` is not a valid Maven invocation (`pitest` is a plugin prefix, not a
lifecycle phase). Use the command in the table above.

## 7. Definition of Done

A change is done only when **all** of the following hold:

- [ ] Tests green locally (`./mvnw verify`; for console changes also `npm test`, `npm run build`,
      `npx playwright test`) **and** in CI.
- [ ] No new warnings (compiler, build, test output, Spotless).
- [ ] OpenAPI is updated (annotations/descriptions accurate; `/v3/api-docs` reflects the change).
- [ ] The relevant README section (or `docs/reference.md`, `docs/runbook.md`) is updated, links still resolve
      (`link-check`), and `CHANGELOG.md` has a line under `[Unreleased]`.
- [ ] No secrets committed: no tokens, keys or real credentials. Local dev credentials guard only
      throwaway containers with synthetic data.
- [ ] Honesty rule respected: any claimed number is reproducible.

## 8. Dependencies and supply chain

- Pin exact versions. Prefer versions managed by the Spring Boot BOM; pin anything else explicitly.
- GitHub Actions are pinned to full commit SHAs (with the tag in a comment). Docker base images are pinned
  by digest. Dependabot proposes updates weekly.
- Do not add a dependency without saying why in the PR.
